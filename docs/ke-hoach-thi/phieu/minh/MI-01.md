## 1. Prompt dán cho Claude

Mở Claude trong thư mục repo thi (đã có `docs/`), dán nguyên khối dưới đây. Claude tự tạo nhánh `minh/mi-01`, đọc tài liệu, code, kiểm, commit, push và mở PR. Việc của bạn: trả lời khi Claude hỏi, cho phép chạy lệnh git/gh khi được hỏi, rồi làm Mục 2.

```text
Bạn đang làm phiếu MI-01 (Contracts engine và kiểu nối với Tầng 0) cho Minh trong repo thi SimpliFey. Repo bắt đầu trống, mọi code được viết mới theo tài liệu trong thư mục docs/. Thư mục docs/ là tài liệu của đội, đã có trên main: không sửa, không xóa, không add file nào trong docs/. Làm lần lượt 6 bước dưới đây, xong bước nào báo ngắn bước đó.

BƯỚC 0 — Nhánh: chạy `git checkout main` rồi `git pull`, sau đó `git checkout -b minh/mi-01` (nếu nhánh đã có thì `git checkout minh/mi-01` rồi `git merge main`). Chạy `git status`: nếu thấy có thay đổi trong thư mục docs/ thì DỪNG và báo tôi, không commit thay đổi đó.

Tên file, tên hàm, tên kiểu và chữ ký ghi trong phiếu là hợp đồng với các thành viên khác: dùng đúng, không tự đổi.

BƯỚC 2 — Code: Hãy đọc kỹ file `docs/spec/02_CONTRACTS.md` (Mục 3, Mục 4), `docs/spec/10_ENGINE_INGEST.md` (Mục 0) và `docs/spec/11_ENGINE_DO_THI.md` (Mục 0) cùng với file contracts `src/contracts/base.ts` (nếu đã có) trước khi viết code. Tạo mới và chỉ chỉnh sửa các file sau: `src/contracts/engine.ts`, `src/contracts/engine-internal.ts`; đảm bảo export đúng tên của spec: LanguageSupportInfo, ProjectFingerprint, NodeTitleSource, ExecutionTraceStep, UncleBobMetrics, EntityOp, HybridArchitecturalNode, GraphEdge, IngestionErrorCode, IngestionReport, RepoSnapshotKey, StaticEngineResult, ClientStaticEngineResult, LanguageAdapter, GithubRepoInfo, ProbeResult, SymbolDefinition, FunctionCallEdge, IngestSource, VirtualFileOrigin, IngestOutput. BƯỚC 3 — Kiểm: chạy `npm run typecheck`, `npm run lint`, `npm test` và sửa tới khi cả 3 xanh. Chỉ sửa các file trong mục "File được sửa" của phiếu; cần sửa file khác thì DỪNG và báo tôi.

BƯỚC 4 — Commit: trước khi commit chạy `git fetch origin` rồi `git merge origin/main`, có xung đột thì gỡ và chạy lại 3 lệnh kiểm. Chia thành nhiều commit nhỏ (mỗi commit khoảng 200 dòng trở xuống), message theo mục "Commit dự kiến" của phiếu. Chỉ `git add <đường-dẫn>` từng file thuộc phiếu; không dùng `git add -A`, `git add .` hay `git add -f`. Không dùng `--date`, không đổi thời gian commit, không `--amend` hay rebase commit đã push.

BƯỚC 5 — Push và PR: chạy `git push -u origin minh/mi-01`, rồi `gh pr create --base main --head minh/mi-01 --title "MI-01: Contracts engine và kiểu nối với Tầng 0" --body "<nội dung>"`. Nội dung PR gồm: mã phiếu MI-01, danh sách file đã sửa, kết quả 3 lệnh kiểm, cách thử tay theo mục "Tiêu chí đạt". KHÔNG tự merge PR. In link PR cho tôi.

Nếu khoảng 30 phút vẫn chưa xong, hoặc gặp lỗi quyền, lỗi đăng nhập GitHub (`gh auth status`), xung đột không tự gỡ được, hãy dừng và báo tôi đang kẹt ở bước nào.
```
