## 1. Prompt dán cho Claude

Mở Claude trong thư mục repo thi (đã có `docs/`), dán nguyên khối dưới đây. Claude tự tạo nhánh `minh/mi-07`, đọc tài liệu, code, kiểm, commit, push và mở PR. Việc của bạn: trả lời khi Claude hỏi, cho phép chạy lệnh git/gh khi được hỏi, rồi làm Mục 2.

```text
Bạn đang làm phiếu MI-07 (Chạy repo TS dự phòng, sửa bài lỗi, test tất định) cho Minh trong repo thi SimpliFey. Repo bắt đầu trống, mọi code được viết mới theo tài liệu trong thư mục docs/. Thư mục docs/ là tài liệu của đội, đã có trên main: không sửa, không xóa, không add file nào trong docs/. Làm lần lượt 6 bước dưới đây, xong bước nào báo ngắn bước đó.

BƯỚC 0 — Nhánh: chạy `git checkout main` rồi `git pull`, sau đó `git checkout -b minh/mi-07` (nếu nhánh đã có thì `git checkout minh/mi-07` rồi `git merge main`). Chạy `git status`: nếu thấy có thay đổi trong thư mục docs/ thì DỪNG và báo tôi, không commit thay đổi đó.

BƯỚC 1 — Đọc: đọc hết file `docs/ke-hoach-thi/phieu/minh/MI-07.md` (nhất là mục Yêu cầu, Bẫy đã biết, Tiêu chí đạt), phần "Luật chung cho mọi phiếu" ở đầu `docs/ke-hoach-thi/02_PHIEU_THIEN.md`. Tên file, tên hàm, tên kiểu và chữ ký ghi trong phiếu là hợp đồng với các thành viên khác: dùng đúng, không tự đổi.

BƯỚC 2 — Code: Hãy đọc kỹ file `docs/spec/50_TEST_VA_FIXTURE.md` (Mục 4, Mục 5) và `docs/spec/11_ENGINE_DO_THI.md` (Mục 11) cùng với file `src/server/engine/graph/*.ts` và `src/server/engine/index.ts` trước khi viết code. Tạo mới và chỉ chỉnh sửa các file sau: các file trong `src/server/engine/graph/`, `src/server/engine/index.ts` và `src/server/engine/__tests__/repo-du-phong.test.ts`; giữ nguyên mọi chữ ký hàm đang export. Triển khai luồng xử lý gồm: sửa lần lượt các lỗi trong danh sách đính kèm (bài 0 bước, bài từ file test có bước <module> làm Capstone, tên khó hiểu), mỗi lỗi 1 test hồi quy dùng dữ liệu tự dựng; lưu ý không thêm tính năng mới, và tuyệt đối không khóa cứng người dùng (bài lỗi bị bỏ chứ không làm hỏng bản đồ). Tránh các lỗi sau: đổi chữ ký hàm, làm đổi node_id của bài không lỗi, đưa code repo của người khác vào test; sau khi viết xong, hãy tự chạy lệnh `npm run typecheck`, `npm run lint`, `npm test` để đảm bảo pass 100%.

BƯỚC 3 — Kiểm: chạy `npm run typecheck`, `npm run lint`, `npm test` và sửa tới khi cả 3 xanh. Chỉ sửa các file trong mục "File được sửa" của phiếu; cần sửa file khác thì DỪNG và báo tôi.

BƯỚC 4 — Commit: trước khi commit chạy `git fetch origin` rồi `git merge origin/main`, có xung đột thì gỡ và chạy lại 3 lệnh kiểm. Chia thành nhiều commit nhỏ (mỗi commit khoảng 200 dòng trở xuống), message theo mục "Commit dự kiến" của phiếu. Chỉ `git add <đường-dẫn>` từng file thuộc phiếu; không dùng `git add -A`, `git add .` hay `git add -f`. Không dùng `--date`, không đổi thời gian commit, không `--amend` hay rebase commit đã push.

BƯỚC 5 — Push và PR: chạy `git push -u origin minh/mi-07`, rồi `gh pr create --base main --head minh/mi-07 --title "MI-07: Chạy repo TS dự phòng, sửa bài lỗi, test tất định" --body "<nội dung>"`. Nội dung PR gồm: mã phiếu MI-07, danh sách file đã sửa, kết quả 3 lệnh kiểm, cách thử tay theo mục "Tiêu chí đạt". KHÔNG tự merge PR. In link PR cho tôi.

Nếu khoảng 30 phút vẫn chưa xong, hoặc gặp lỗi quyền, lỗi đăng nhập GitHub (`gh auth status`), xung đột không tự gỡ được, hãy dừng và báo tôi đang kẹt ở bước nào.
```

## 2. Sau khi Claude mở PR (việc của Minh)

1. Mở link PR Claude in ra. Chờ CI (`ci`) xanh. CI đỏ thì dán lỗi CI cho Claude sửa trên cùng nhánh rồi push lại.
2. Thử tay theo mục **Tiêu chí đạt** bên dưới.
3. Bấm **Merge pull request ⇒ Create a merge commit** (không Squash, không Rebase).
4. Nhắn nhóm: "đã merge MI-07". Người đang làm phiếu khác tự `git pull`.
