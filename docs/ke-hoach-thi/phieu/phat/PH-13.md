```text
Bạn đang làm phiếu PH-13 (So ảnh với prototype.html và sửa lệch (ghi chú 5)) cho Phát trong repo thi SimpliFey. Repo bắt đầu trống, mọi code được viết mới theo tài liệu trong thư mục docs/. Thư mục docs/ là tài liệu của đội, đã có trên main: không sửa, không xóa, không add file nào trong docs/. Làm lần lượt 6 bước dưới đây, xong bước nào báo ngắn bước đó.

BƯỚC 0 — Nhánh: chạy `git checkout main` rồi `git pull`, sau đó `git checkout -b phat/ph-13` (nếu nhánh đã có thì `git checkout phat/ph-13` rồi `git merge main`). Chạy `git status`: nếu thấy có thay đổi trong thư mục docs/ thì DỪNG và báo tôi, không commit thay đổi đó.

BƯỚC 1 — Đọc: đọc hết file `docs/ke-hoach-thi/phieu/phat/PH-13.md` (nhất là mục Yêu cầu, Bẫy đã biết, Tiêu chí đạt), phần "Luật chung cho mọi phiếu" ở đầu `docs/ke-hoach-thi/02_PHIEU_THIEN.md`, và bảng "Hợp đồng UI ⇄ API" cùng danh sách action của store ở đầu `docs/ke-hoach-thi/02_PHIEU_PHAT.md`. Tên file, tên hàm, tên kiểu và chữ ký ghi trong phiếu là hợp đồng với các thành viên khác: dùng đúng, không tự đổi.

BƯỚC 2 — Code: Hãy đọc kỹ file `docs/prototype.html` (toàn trang), `docs/spec/30_UI.md` (Mục 11) và `docs/ke-hoach-thi/07_GHI_CHU_VA_CHOT.md` (ghi chú 5) cùng với các component trong `src/components/learn/`, `src/components/code/` trước khi viết code. Tạo mới và chỉ chỉnh sửa các file sau: chỉ các file đã thuộc các phiếu PH-01 … PH-12; giữ nguyên tên component và props đang export. Triển khai luồng xử lý gồm: sửa từng lệch trong danh sách đính kèm về bố cục, nhãn chữ, thành phần, luồng cho khớp prototype, màu giữ theo Mục 11; lưu ý không chỉnh pixel, không thêm tính năng, và tuyệt đối không khóa cứng người dùng (không thêm bước chặn nào vào luồng học). Tránh các lỗi sau: đổi tên props làm hỏng trang, đổi màu theo prototype thay vì theo Mục 11; sau khi viết xong, hãy tự chạy lệnh `npm run typecheck`, `npm run lint`, `npm test` và chạy lại kịch bản A ở `/learn?fixture=1` để đảm bảo pass 100%.

BƯỚC 3 — Kiểm: chạy `npm run typecheck`, `npm run lint`, `npm test` và sửa tới khi cả 3 xanh. Chỉ sửa các file trong mục "File được sửa" của phiếu; cần sửa file khác thì DỪNG và báo tôi.

BƯỚC 4 — Commit: trước khi commit chạy `git fetch origin` rồi `git merge origin/main`, có xung đột thì gỡ và chạy lại 3 lệnh kiểm. Chia thành nhiều commit nhỏ (mỗi commit khoảng 200 dòng trở xuống), message theo mục "Commit dự kiến" của phiếu. Chỉ `git add <đường-dẫn>` từng file thuộc phiếu; không dùng `git add -A`, `git add .` hay `git add -f`. Không dùng `--date`, không đổi thời gian commit, không `--amend` hay rebase commit đã push.

BƯỚC 5 — Push và PR: chạy `git push -u origin phat/ph-13`, rồi `gh pr create --base main --head phat/ph-13 --title "PH-13: So ảnh với prototype.html và sửa lệch (ghi chú 5)" --body "<nội dung>"`. Nội dung PR gồm: mã phiếu PH-13, danh sách file đã sửa, kết quả 3 lệnh kiểm, cách thử tay theo mục "Tiêu chí đạt". KHÔNG tự merge PR. In link PR cho tôi.

Nếu khoảng 30 phút vẫn chưa xong, hoặc gặp lỗi quyền, lỗi đăng nhập GitHub (`gh auth status`), xung đột không tự gỡ được, hãy dừng và báo tôi đang kẹt ở bước nào.
```
