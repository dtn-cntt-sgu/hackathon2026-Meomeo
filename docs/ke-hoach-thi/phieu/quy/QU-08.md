# QU-08 · Hoàn thiện mảng độc lập và commit cuối

> Mục lục phiếu của Quý: [`02_PHIEU_QUY.md`](../../02_PHIEU_QUY.md) · Luật chung: [`02_PHIEU_THIEN.md`](../../02_PHIEU_THIEN.md)

## 1. Prompt dán cho Codex

Mở Codex trong thư mục repo thi (đã có `docs/`), dán nguyên khối dưới đây. Codex tự tạo nhánh `quy/qu-08`, đọc tài liệu, code, kiểm, commit, push và mở PR. Việc của bạn: trả lời khi Codex hỏi, cho phép chạy lệnh git/gh khi được hỏi, rồi làm Mục 2.

**Nếu Codex không chạy được `git push` hoặc `gh pr create`** (bị chặn mạng hay quyền), Quý tự chạy 2 lệnh ở BƯỚC 5 trong terminal của mình rồi dán link PR cho Codex biết.

```text
Bạn đang làm phiếu QU-08 (Hoàn thiện mảng độc lập và commit cuối) cho Quý trong repo thi SimpliFey. Repo bắt đầu trống, mọi code được viết mới theo tài liệu trong thư mục docs/. Thư mục docs/ là tài liệu của đội, đã có trên main: không sửa, không xóa, không add file nào trong docs/. Làm lần lượt 6 bước dưới đây, xong bước nào báo ngắn bước đó.

BƯỚC 0 — Nhánh: chạy `git checkout main` rồi `git pull`, sau đó `git checkout -b quy/qu-08` (nếu nhánh đã có thì `git checkout quy/qu-08` rồi `git merge main`). Chạy `git status`: nếu thấy có thay đổi trong thư mục docs/ thì DỪNG và báo tôi, không commit thay đổi đó.

BƯỚC 1 — Đọc: đọc hết file `docs/ke-hoach-thi/phieu/quy/QU-08.md` (nhất là mục Yêu cầu, Bẫy đã biết, Tiêu chí đạt), phần "Luật chung cho mọi phiếu" ở đầu `docs/ke-hoach-thi/02_PHIEU_THIEN.md`. Tên file, tên hàm, tên kiểu và chữ ký ghi trong phiếu là hợp đồng với các thành viên khác: dùng đúng, không tự đổi.

BƯỚC 2 — Code: Hãy đọc kỹ file `docs/spec/30_UI.md` (Mục 11) cùng với các file trong `src/components/how-it-works/` và `src/components/history/` trước khi viết code. Tạo mới và chỉ chỉnh sửa các file sau: chỉ file trong `src/app/how-it-works/`, `src/components/how-it-works/`, `src/app/history/`, `src/components/history/`; giữ nguyên tên component và hàm đang export. Triển khai luồng xử lý gồm: sửa bố cục ở 1366×768 và 375px, thứ tự Tab và Enter, tắt hiệu ứng khi prefers-reduced-motion; lưu ý không thêm khối hay tính năng mới, và tuyệt đối không khóa cứng người dùng (không thêm bước chặn nào). Tránh các lỗi sau: sửa file ngoài mảng, đổi tên export; sau khi viết xong, hãy tự chạy lệnh `npm run typecheck`, `npm run lint` để đảm bảo pass 100%.

BƯỚC 3 — Kiểm: chạy `npm run typecheck`, `npm run lint`, `npm test` và sửa tới khi cả 3 xanh. Chỉ sửa các file trong mục "File được sửa" của phiếu; cần sửa file khác thì DỪNG và báo tôi.

BƯỚC 4 — Commit: trước khi commit chạy `git fetch origin` rồi `git merge origin/main`, có xung đột thì gỡ và chạy lại 3 lệnh kiểm. Chia thành nhiều commit nhỏ (mỗi commit khoảng 200 dòng trở xuống), message theo mục "Commit dự kiến" của phiếu. Chỉ `git add <đường-dẫn>` từng file thuộc phiếu; không dùng `git add -A`, `git add .` hay `git add -f`. Không dùng `--date`, không đổi thời gian commit, không `--amend` hay rebase commit đã push.

BƯỚC 5 — Push và PR: chạy `git push -u origin quy/qu-08`, rồi `gh pr create --base main --head quy/qu-08 --title "QU-08: Hoàn thiện mảng độc lập và commit cuối" --body "<nội dung>"`. Nội dung PR gồm: mã phiếu QU-08, danh sách file đã sửa, kết quả 3 lệnh kiểm, cách thử tay theo mục "Tiêu chí đạt". KHÔNG tự merge PR. In link PR cho tôi.

Nếu khoảng 30 phút vẫn chưa xong, hoặc gặp lỗi quyền, lỗi đăng nhập GitHub (`gh auth status`), xung đột không tự gỡ được, hãy dừng và báo tôi đang kẹt ở bước nào.
```

## 2. Sau khi Codex mở PR (việc của Quý)

1. Mở link PR Codex in ra. Chờ CI (`ci`) xanh. CI đỏ thì dán lỗi CI cho Codex sửa trên cùng nhánh rồi push lại.
2. Thử tay theo mục **Tiêu chí đạt** bên dưới.
3. Bấm **Merge pull request ⇒ Create a merge commit** (không Squash, không Rebase).
4. Nhắn nhóm: "đã merge QU-08". Người đang làm phiếu khác tự `git pull`.
